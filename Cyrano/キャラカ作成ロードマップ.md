# FF14 キャラカ(キャラクターカード)ジェネレータ 作成ロードマップ

最終更新: 2026-10-01

## 1. 目的・コンセプト

- FF14 のキャラクターカード画像を作る HTML ツール
- **差別化ポイント: テキストブロックを自由に変更できること**(配置・内容・数を自由に編集)
- ロードストーン ID を入れるとキャラ情報を自動取得できるようにしたい
- 公開先は **GitHub Pages** を想定

## 3. 調査結果: Lodestone からの取得

### テスト用ID
- **`22997788`**(Cyrano Ott)← 以後こちらを使う

### 取得方法
- URL: `https://jp.finalfantasyxiv.com/lodestone/character/{ID}/`
  - curl(User-Agent: `Mozilla/5.0`)で **200 OK、ログイン不要**
- ジョブレベル: `https://jp.finalfantasyxiv.com/lodestone/character/{ID}/class_job/`(200 確認済、HTML構造は未調査)

### 取れる項目(HTML の class 名)
| 項目 | 抽出元 |
|---|---|
| キャラ名 | `frame__chara__name">名前` |
| 称号 | `frame__chara__title">称号` |
| ワールド/DC | `frame__chara__world">` 内の `</i>` の後(例: `Leviathan [Primal]`) |
| 種族/部族/性別等 | `character__profile__data__detail` 内の `character-block` |
| 自己紹介 | `character__selfintroduction">` |
| FC名 | `character__freecompany__name` 内の `<h4><a>` |
| 顔画像 | `https://img2.finalfantasyxiv.com/f/....fc0.jpg?...` |
| 全身画像 | `https://img2.finalfantasyxiv.com/f/....fl0.jpg?...` |

- 本人が非公開にしている項目(自己紹介・ジョブ等)はログイン無しでは取れない → 空欄扱いにする

### 重大な制約: CORS
- Lodestone のレスポンスに **`Access-Control-Allow-Origin` が無い**
- → **GitHub Pages の HTML(ブラウザ)から直接 fetch は不可**。何らかのサーバー側処理が必要

### 第三者サービスの状況(2026-10-01 テスト、ID 22997788、各2回)
| サービス | 結果 | 原因 |
|---|---|---|
| allorigins(公開CORSプロキシ) | 522 | プロキシ自体がダウン |
| XIVAPI `xivapi.com/character/{ID}` | 500 | 本文 "Lodestone returned some error codes: 403" → XIVAPI が Lodestone にブロックされている |

→ **公開プロキシ・第三者APIは当てにしない**。共有サーバーは Lodestone にブロックされうるので、自前でもキャッシュでアクセス数を抑えること。

## 6. Cloudflare Workers メモ

- 提供: Cloudflare, Inc.(米国、上場企業、CDN/DDoS対策大手。東京・大阪にもDCあり)
- 実体: 自分のJS関数をCloudflare上で動かすサーバーレス。OS管理・常時起動なし
- 無料枠: **1日10万リクエスト**、CPU 10ms/リクエスト、クレカ不要、超過時はエラーになるだけ(勝手に課金されない)
- **使う側(ユーザー)はログイン一切不要**。Cloudflareアカウントは作者のみ
- 作業手順(CLI不要、ブラウザだけ):
  1. cloudflare.com でアカウント作成
  2. Workers & Pages → Create Worker → 名前を付けて Deploy
  3. Edit code でコードを貼って Deploy → `https://<名前>.<アカウント>.workers.dev/?id=22997788`
- **未検証リスク**: Cloudflare の IP から Lodestone が素直に返すか(XIVAPI は 403 を食らっている)。作ったらまず確認する
- 対策: Cache API で同一IDを数分〜10分キャッシュ、User-Agent 設定、`Access-Control-Allow-Origin` は自分の Pages の URL のみ許可

### Worker 実装: [`characa/worker.js`](characa/worker.js)
- `GET /?id={ID}` → キャラ情報 JSON
  - `name, title, server, dataCenter, race, tribe, gender, birthday, guardian, hometown, grandCompany, grandCompanyRank, freeCompany, selfIntroduction, id, levels[{name, level}]`
  - `levels`: 未習得は `"-"`。ジョブ未取得時はクラス名(例: 剣術士)。末尾にエレメンタル/レジスタンス/ナレッジレベルも含まれる
  - 自己紹介「未設定」は空文字。ID不正 → 400、キャラ無し → 404、Lodestone異常 → 502
- ~~`GET /img?url=...`(画像中継)~~ → 2026-10-02 に削除。返却 JSON からも `face` `image` を外した。**ダッシュボードで worker.js を貼り替えて再デプロイするまでは、公開中の Worker は古いコードのまま**(フロントは画像URLを無視するので動作に問題はない)
- キャッシュ: JSON 10分 / 画像 1日。キャッシュは CORS ヘッダ無しで保存し、返却時に付与
- CORS: `ALLOWED_ORIGINS` に一致する Origin のみ許可。**GitHub Pages の URL が決まったら `https://<user>.github.io` を書き換える**(ローカル開発用に `localhost:8000` も許可済み)
- ローカルテスト(2026-10-01、Node 24 + `caches` モック、実 Lodestone): ID `22997788` / `1` で全項目取得OK、不正ID・不正ホスト・別オリジンの挙動もOK
  - 注: `22997788` のワールドは現在 `Ridill [Gaia]`
