## 3. 調査結果: Lodestone からの取得

### テスト用ID
- **`22997788`**(Cyrano Ott)← 以後こちらを使う

### 取得方法
- URL: `https://jp.finalfantasyxiv.com/lodestone/character/{ID}/`
  - curl(User-Agent: `Mozilla/5.0`)で **200 OK、ログイン不要**
- ジョブレベル: `https://jp.finalfantasyxiv.com/lodestone/character/{ID}/class_job/`(200 確認済、HTML構造は未調査)

### 取れる項目(HTML の class 名)
| 項目 | 抽出元 |
|---|---|
| キャラ名 | `frame__chara__name">名前` |
| 称号 | `frame__chara__title">称号` |
| ワールド/DC | `frame__chara__world">` 内の `</i>` の後(例: `Leviathan [Primal]`) |
| 種族/部族/性別等 | `character__profile__data__detail` 内の `character-block` |
| 自己紹介 | `character__selfintroduction">` |
| FC名 | `character__freecompany__name` 内の `<h4><a>` |
| 顔画像 | `https://img2.finalfantasyxiv.com/f/....fc0.jpg?...` |
| 全身画像 | `https://img2.finalfantasyxiv.com/f/....fl0.jpg?...` |

- 本人が非公開にしている項目(自己紹介・ジョブ等)はログイン無しでは取れない → 空欄扱いにする

### 重大な制約: CORS
- Lodestone のレスポンスに **`Access-Control-Allow-Origin` が無い**
- → **GitHub Pages の HTML(ブラウザ)から直接 fetch は不可**。何らかのサーバー側処理が必要

### 第三者サービスの状況(2026-10-01 テスト、ID 22997788、各2回)
| サービス | 結果 | 原因 |
|---|---|---|
| allorigins(公開CORSプロキシ) | 522 | プロキシ自体がダウン |
| XIVAPI `xivapi.com/character/{ID}` | 500 | 本文 "Lodestone returned some error codes: 403" → XIVAPI が Lodestone にブロックされている |

→ **公開プロキシ・第三者APIは当てにしない**。共有サーバーは Lodestone にブロックされうるので、自前でもキャッシュでアクセス数を抑えること。

## 4. 競合サイトの仕組み

### characa.kkimu.dev
- フロント: React(Vite)+ react-konva(Canvas描画)+ i18next(日英)
- API: `https://characa.onrender.com/character?id={ID}`(Render 上の別サーバー、`access-control-allow-origin: *`)
- 返却 JSON 例: `name, server, data_center, levels[](全ジョブ), race, tribe, gender, birthday, guardian, hometown, grand_company, grand_company_rank, free_company, free_company_image, image(全身画像)`
- 機能: Lodestone IDの調べ方の説明画像、フォント選択、PNG保存、X共有、「FFXIV著作物利用条件」表記
- バンドル内に Konva の「Tainted Canvas」への言及あり → 画像CORS対策をしている模様
- ※他人のAPIなので無断利用はしない

### knt-a.com/c-card
- フロント: Vue + Vuetify + axios
- API: 同一ドメインの自前サーバー(nginx)
  - `https://knt-a.com/ffxiv/levels/{ID}` → `[{"id":"PLD","level":"100"}, ...]`
  - ほかに `/ffxiv/achievements/...`、`/ffxiv/ldst_id_search/`
  - CORS ヘッダ無し(同一オリジン前提なので外部から呼べない)
- カードはテンプレートJSON(`ui` / `card`)読み込み方式
- カード画面で確認できたAPI呼び出しはジョブレベル取得のみ(名前等は手入力?未確認)

**結論: Lodestone 取得をブラウザだけで完結させているサイトは無い。**

## 6. Cloudflare Workers メモ

- 提供: Cloudflare, Inc.(米国、上場企業、CDN/DDoS対策大手。東京・大阪にもDCあり)
- 実体: 自分のJS関数をCloudflare上で動かすサーバーレス。OS管理・常時起動なし
- 無料枠: **1日10万リクエスト**、CPU 10ms/リクエスト、クレカ不要、超過時はエラーになるだけ(勝手に課金されない)
- **使う側(ユーザー)はログイン一切不要**。Cloudflareアカウントは作者のみ
- 作業手順(CLI不要、ブラウザだけ):
  1. cloudflare.com でアカウント作成
  2. Workers & Pages → Create Worker → 名前を付けて Deploy
  3. Edit code でコードを貼って Deploy → `https://<名前>.<アカウント>.workers.dev/?id=22997788`
- **未検証リスク**: Cloudflare の IP から Lodestone が素直に返すか(XIVAPI は 403 を食らっている)。作ったらまず確認する
- 対策: Cache API で同一IDを数分〜10分キャッシュ、User-Agent 設定、`Access-Control-Allow-Origin` は自分の Pages の URL のみ許可

### Worker コード案(たたき台、未デプロイ)
```js
export default {
  async fetch(request, env, ctx) {
    const url = new URL(request.url);
    const id = url.searchParams.get("id");
    const cors = { "Access-Control-Allow-Origin": "https://<user>.github.io" };

    if (!/^\d+$/.test(id ?? "")) {
      return new Response(JSON.stringify({ error: "invalid id" }), { status: 400, headers: cors });
    }

    // 同じIDは一定時間キャッシュして、Lodestoneへのアクセスを減らす
    const cache = caches.default;
    const cacheKey = new Request(url.toString());
    const hit = await cache.match(cacheKey);
    if (hit) return hit;

    const res = await fetch(`https://jp.finalfantasyxiv.com/lodestone/character/${id}/`, {
      headers: { "User-Agent": "Mozilla/5.0" },
    });
    if (!res.ok) {
      return new Response(JSON.stringify({ error: res.status }), { status: res.status, headers: cors });
    }
    const html = await res.text();

    const pick = (re) => (html.match(re)?.[1] ?? "").trim();
    const data = {
      name:  pick(/frame__chara__name">([^<]*)/),
      title: pick(/frame__chara__title">([^<]*)/),
      world: pick(/frame__chara__world">.*?<\/i>([^<]*)/),
      image: pick(/(https:\/\/img2\.finalfantasyxiv\.com\/f\/[^"]*fl0\.jpg[^"]*)/),
    };

    const out = new Response(JSON.stringify(data), {
      headers: { ...cors, "Content-Type": "application/json", "Cache-Control": "max-age=600" },
    });
    ctx.waitUntil(cache.put(cacheKey, out.clone()));
    return out;
  },
};
```

## 7. 注意点(どの案でも共通)

- **PNG書き出し**: Lodestone画像を canvas に描くと tainted になり `toDataURL` 不可 → Worker で画像中継して CORS ヘッダを付ける(案A)、またはユーザーに画像をアップロードしてもらう(案C)
