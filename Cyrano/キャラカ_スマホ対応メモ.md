## 2026-10-02 に作った画面の構成(ユーザーのラフ画に合わせた)
- **制作エリア**(横幅はいつも画面いっぱい。スマホ縦向きは高さを横幅までにとどめるので、正方形か横長になる)にグリッド線を引き、その中にカードを置く。拡大縮小とグリッドのボタンは制作エリアのすぐ下
  - カードの倍率は「長さ1920が制作エリアの92%に収まる倍率」で固定する(`app.js` の `layoutStage`、`STAGE_REF = 1920`)。**縦長でも横長でも同じ倍率**になり、縦長のカードでも画面いっぱいには広がらない
  - グリッドはカードの左上に揃え、カード上の120pxごとに1マス。右下の「グリッド」ボタンで表示・非表示を切り替え、設定はこのブラウザに保存する
  - カードの外側(余白)を押すと、選択を外す
- **下に付箋みたいなタブのシート**:デザイン / キャラ / 要素 / カード(2026-10-02 に「編集」を「要素」へ統合)
  - タブごとに色が違い、選んでいるタブは色が濃く、少し上に飛び出す。シートの上の線もそのタブの色になる
  - カード上の要素を押したときは、自動で「要素」タブを開く。一覧から選んだときはタブを動かさない
  - 最後に開いていたタブをこのブラウザに覚えておく
  - 著作物の表記はシートの一番下に置いている
- 縦に並べる(スマホ縦向き):上にヘッダー → 制作エリア → シート。シートの高さは最低230pxを確保し、足りないときは制作エリアのほうを小さくする
- 横に並べる(幅900px以上、または横向きで幅560px以上):左に制作エリア、右にシート(幅は 400px か画面の56% の小さいほう)
- ページ全体はスクロールせず、シートの中だけをスクロールする(`body { overflow: hidden }`)
- このとき一緒に入れたスマホ向けの設定:`100dvh`、`viewport-fit=cover` と切り欠き部分の余白、ボタンの `touch-action: manipulation`、カード上の長押しメニューを止める
- 確認したサイズ:320×568 / 375×635 / 812×375 / 568×320 / 1280×760。横方向のはみ出しはなく、タブの文字も切れない

## 目的
- スマホで使うことを前提にする
- **iPhone mini・SE のような小さい画面(幅 320〜375px)でもレイアウトが崩れない**ようにする(ユーザーが特に気にしている点)

## やりたいこと(案)

### 1. 画面の構成 → 完了(上の「2026-10-02 に作った画面の構成」)

### 2. 指での操作
- タップで選択、ドラッグで移動(今のままで動く)
- ~~2本指でつまむ(ピンチ)で要素の大きさを変える~~ → **2026-10-02 に「表示の拡大縮小」に使うことにした**(ユーザーが制作エリアで拡大したいと依頼したため)。要素の大きさは右下のハンドルで変える
- **Alt+ドラッグの代わり**:画像を選ぶと「中の画像を動かす」の切り替えボタンが出て、オンのときはドラッグで枠の中の位置を調整する
- 右下の拡大縮小ハンドルを指で押しやすい大きさにする(14px → 28px程度。指で操作する端末だけ)
- キーボード操作(矢印キー・Delete)はスマホでは使えないので、ボタンで同じことができるようにする

### 3. 選択中の要素のボタン(タブ式にしたので、必要かどうかは要検討。今は要素を選ぶと「編集」タブが開く)
- 要素を選ぶと、**カードのすぐ下に小さなボタン列**を出す:「編集」「前面」「背面」「複製」「削除」、画像なら「中の画像を動かす」
- 「編集」を押すと、パネルの「選択中の要素」までスクロールする(固定したヘッダーとカードの下に隠れないよう `scroll-margin-top` を指定する)
- PC では右のパネルが常に見えているので、このボタン列は出さない

### 4. 保存(iPhone では特に注意)
- スマホでは、PNGをすぐにダウンロードさせず、**保存用の画面に画像を表示**する
  - 「画像を長押しで写真に保存」と案内する
  - 「写真に保存 / 共有」ボタン(Web Share API。使える端末だけ表示)
  - 「ファイルとしてダウンロード」「閉じる」
- 理由:iOS Safari は「ボタンを押した直後」でないと共有画面を出せない。画像の準備(最大3秒待つ)を挟むと、共有が拒否されることがあるため、準備が済んでから改めてボタンを押してもらう

### 5. 説明文
- 操作のヒントを、指で操作する端末では指向けの文章にする
  - 例:「タップで選択 / ドラッグで移動 / 2本指でつまんで拡大縮小」
- 画像欄の「ホイールでズーム / Alt+ドラッグ」も、指向けの説明に切り替える

## 気をつける点(崩れやすいところ)

### iOS Safari 特有
- **入力欄の文字が16px未満だと、タップしたときに画面が勝手に拡大される**。スマホでは input / select / textarea を16px以上にする(今は14px前後なので要対応)
- **`100vh` はアドレスバーの分だけずれる**。`100dvh`(未対応ブラウザには `vh` を予備に)を使う
- 切り欠き(ノッチ)やホームバーに重ならないよう、`viewport-fit=cover` と `env(safe-area-inset-*)` で余白を取る
- 長押しで出るメニューや文字選択を、カードの上では出さない(`-webkit-touch-callout: none`、`user-select: none`)
- ボタンのダブルタップで拡大されないよう `touch-action: manipulation` を指定する
- カードの上は `touch-action: none` なので、**カードに触れてもページはスクロールしない**。カードを固定表示にして、スクロールはパネル側で行う作りにするのはこのため
- `input type="color"` は iOS 14以降で使える。古い端末では見た目が違う可能性がある
- 写真の選択(`accept="image/*"`)は、写真ライブラリ・カメラ・ファイルから選べる。今のままでよい

### 幅320pxで崩れやすいところ
- ヘッダー:タイトルと「PNGで保存」が1行に入るか → 入らなければタイトルを縮めるか、ボタンだけにする
- パネルの2列の入力欄:ラベルが長いもの(「折り返し幅(0=しない)」など)が折り返して高さがそろわない → 1列にするか、ラベルを短くする
- 色欄(配色の選択+色の四角)が半分の幅に収まるか
- デザイン一覧の2列のサムネイル、配色ボタンの並び
- 「要素」の追加ボタン(＋テキスト 等)、選択中の要素の操作ボタンの折り返し
- 横にはみ出してページが左右にスクロールしないこと(`overflow-x` を確認。はみ出す要素があれば `min-width: 0` で対処)

### 指での操作
- ボタン・タブ・チップは、押せる高さを40px前後にする(今は小さいボタンが多い)
- 要素同士が重なっていて小さいものを選びにくい → 「要素」一覧からも選べることを案内する
- 2本指の操作を始めたら、1本目のドラッグはやめる(要素が飛ばないように)
- `pointercancel`(着信や通知で操作が途切れたとき)でも、状態をきちんと戻す

### 容量・性能
- 自動保存(localStorage)の容量は、iOS では約5MB。スクショが大きいと保存に失敗する(今もエラー表示はある)
  - 必要なら、スクショを縮める上限(今は長辺2400px)をスマホでは下げる
- サムネイルの描き直しは、操作中に何度も走らないよう今も250ms待ってから描いている。スマホではもう少し長くしてもよい
- 1080×1920 のカードはスマホのメモリでも問題ない想定だが、実機で書き出しを確認する
