# 引き継ぎメモ：カップリング辞典 / キャラクター紹介

最終更新: 2026-09-30

個人で楽しむためのサイト。データはGoogleスプレッドシートで管理し、**コミットしなくても更新が反映される**ことを重視している。

---

## ファイル一覧（`homepage/Cyrano/`）

| ファイル | 役割 |
|---|---|
| `coupling.html` | カップリング辞典ページ（プルダウン2つ → カプ名＋補足） |
| `coupling_api.gs` | カップリング用スプレッドシートに貼る Apps Script |
| `profile.html` | キャラクター紹介ページ（キャラごとのボタン → プロフィール表示） |

- HTMLは他のツールと同じく、CSS/JSをすべて中に書いた1ファイル構成
- 2つのページは**別物**。スプレッドシートもスクリプトも分けている（ユーザーの指定）
- どちらも未コミット

## 全体の仕組み

```
スプレッドシート ──(Apps Script doGet が JSON を返す)──> HTML が fetch して表示
ドライブの画像フォルダ ──(Apps Script がファイル名でキャラにひもづけ)──┘
```

- HTMLの `API_URL` に Apps Script の **`/exec` URL** を設定する（`/dev` はテスト用で、作成者しか開けないので不可）
- `API_URL` が空のときは、HTML内の `SAMPLE_DATA` で表示する
- 「ウェブに公開」（pubhtml）は**使わない**。一度ユーザーが公開したが、今の方式では不要
- データの変更はシートを保存するだけで反映される。**スクリプトのコードを変えたときだけ**、「デプロイを管理」→ 鉛筆アイコン →「新バージョン」で更新する（URLは変わらない）

### 画像
- 2通りの設定方法がある。B列を優先する
  1. `IMAGE_FOLDER_ID` のフォルダに、キャラ名と同じファイル名で画像を置く（例: `キャラA.png`）。拡張子を除いた名前で照合する
  2. シートのB列に、ドライブの共有リンクか画像URLを貼る
- ドライブのリンクは `https://drive.google.com/thumbnail?id=ID&sz=w400`（プロフィール用は w800）に変換して表示する。Google公式のURLではないので、将来使えなくなる可能性がある
- フォルダ・ファイルは「リンクを知っている全員」が閲覧できる設定にしておく必要がある
- `<img referrerpolicy="no-referrer">` を付けている。読み込みに失敗したら、名前の1文字目を丸の中に表示する
- 検討して採用しなかった案：画像をリポジトリに置く方法（コミットが必要になるので、ユーザーが却下）

## カップリング辞典（coupling.html）

### 状態
- **Apps Script はデプロイ済みで、`API_URL` も設定済み**
  `https://script.google.com/macros/s/AKfycbyAH4dvm6m59T2Uqhh6L6IkYsokz1aFbDLf05fi26EjPKV801Hieq9FM5JafksZp57ShQ/exec`
- 最後に確認したときの返り値は `{"characters":[],"couplings":[]}`。シートがまだ空
- ページはこのURLからデータを読み込めることを確認済み。データが空なので「キャラクターがまだ登録されていません」と表示される
- デプロイ済みのスクリプトに `IMAGE_FOLDER_ID` が設定されているかは不明

### シート構成（スプレッドシート「カップリングデータ」）
- 「**名前**」シート: A列 名前 | B列 画像（任意）
  - 当初は「キャラ」というシート名にしていたが、ユーザーのタブ名に合わせて「名前」に変更した
- 「**カップリング**」シート: A列 キャラ1 | B列 キャラ2 | C列 カプ名 | D列 補足
- どちらも1行目は見出しとして読み飛ばす

### 仕様
- 左右のプルダウンでキャラを選ぶと、そのカップリングを表示する
- **順番を区別する**：A×B と B×A は別のカップリングとして登録でき、解説も別々に書ける
  - 選んだ順番どおりの行を優先する。なければ逆の順番の行を探して表示する（画像と表記は、登録された向きの順に並ぶ）
- **同じキャラ同士（A×A）も登録・表示できる**（ユーザーの要望で対応済み）
- どちらにも該当する行がなければ「この組み合わせはまだ登録されていません」
- 補足の中の改行はそのまま表示する（シートではセル内で Alt+Enter）

## キャラクター紹介（profile.html）

### 状態
- **Apps Script はデプロイ済み**。ただし中身のコードが違う可能性がある（下記）
- `API_URL` は設定済み: `https://script.google.com/macros/s/AKfycbzT3eQmYJq7i8Vm3l3h1hNN0ZbJH-jLQvixA9hLLFTl7ZdjaxjsH-AOUmpaVYrmglXS2g/exec`
- ただし2026-09-30時点では、このURLが `{"characters":[],"couplings":[]}` を返していた。カップリング用のコードが貼られている可能性が高いので、`profile_api.gs` への差し替えと新バージョンでのデプロイを依頼中

### シート構成（新しく作るスプレッドシート）
- 「**プロフィール**」シート: A列 名前 | B列 画像（任意） | **C列以降は自由項目**
  - 1行目の見出しがそのまま項目名になる。見出しが空の列は無視する
  - 値は `getDisplayValues()` で取るので、日付などはシートの表示どおりの文字になる
- 「**補足**」シート: A列 名前 | B列 見出し | C列 本文 | D列 画像
  - 1行＝1ブロック。同じキャラの行はシートの上から順に表示する。見出し・本文・画像はどれも空欄にできる
  - 画像欄には、フォルダ内のファイル名（拡張子あり・なしのどちらでも）か、共有リンク・画像URLを書く
  - 補足の画像は w1600、アイコンは w800 で読み込む

### 仕様
- キャラごとのボタン（丸いアイコン＋名前）を並べる。**プルダウンではない**（ユーザーの指定）
- データは起動時に一度だけ読み込み、ボタンを押したらその中から探して表示する
- 押したボタンは色が変わる（`aria-pressed`）
- 中身が空の項目は表示しない。全部空なら「プロフィールはまだ準備中です」
- ボタンを押すとURLの最後に `#キャラ名` が付き、そのURLで直接そのキャラを開ける
- 幅560px以下（スマホ）では縦並びになる
- プロフィールカードの下に補足ブロックを並べる。スクロールして画面に入ると、ふわっと表示する（IntersectionObserver）
  - 画像だけ、または画像＋見出しだけ → 横幅いっぱいに大きく表示（高さは最大85vh、見出しは画像の下に添える）
  - 画像＋本文 → 左右に並べる。画像の位置は左右交互。スマホでは縦並び
  - 文章だけ → 文章だけのカード
  - 画像をタップすると拡大表示（背景のクリックか Esc で閉じる）。読み込めなかった画像は消す

## デザイン共通
- フォントは M PLUS Rounded 1c（Google Fonts）
- ピンク（`--accent: #ff6f9c`）と紫（`--accent2: #b58cff`）のグラデーション、丸みの強いカード
- 表示が切り替わるときにポップアニメーション（`.pop`）
